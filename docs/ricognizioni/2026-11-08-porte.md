Data: 2026-11-08. Tappa B1, Compito 1 (ricognizione). Questo file alimenta le pagine per porta della skill `bottega` e, più avanti, gli adattatori che lanciano un modello senza mani.

Porte: Claude Code, Antigravity (`agy`), Pi (`pi`), GitHub Copilot CLI (`copilot`).

## Come è stata fatta

- **CLI installate** (`claude` 2.1.319, `agy` 1.5.3, `copilot` 1.0.32): solo `--help`, `--version`, l'aiuto dei sottocommandi e la lettura dei file di configurazione e di sessione. Dei file di sessione sono stati letti soltanto i nomi dei campi e dei tipi di record, mai i contenuti. Nessun prompt a un modello, nessuna installazione, nessun login, nessuna modifica di configurazione.
- **Pi** non è installato. Le fonti sono la documentazione (cartella `docs/`) e il README del pacchetto npm `@earendil-works/pi-coding-agent` 1.5.0, scaricato con `npm pack` in una cartella temporanea e letto come testo.
- **Documentazione ufficiale** delle altre porte, letta come testo (elenco in fondo).
- **Sorgenti**: pacchetto npm `@github/copilot` 1.0.32, file `app.js`, `schemas/session-events.schema.json` e `definitions/*.agent.yaml`.
- Notazioni: `~` è la cartella personale; `<…>` è un segnaposto. Ogni fatto è seguito dalla sua fonte: un comando (`claude --help`) o un URL. «non trovato» significa che non l'ho trovato nelle fonti indicate, non che la funzione manchi.
- Le sigle `A1…D8` indicano il capitolo (A Claude Code, B Antigravity, C Pi, D GitHub Copilot CLI) e la domanda, come nella lista del brief (1 installazione locale, 2 lancio senza mani, 3 modelli, 4 trascrizioni e contatori, 5 quota esaurita, 6 versione e accesso, 7 sotto-agenti, 8 skill e istruzioni di progetto).

## A. Claude Code (`claude`)

**A1. Plugin e skill da cartella locale: sì.**
- Un marketplace può essere una cartella: `claude plugin marketplace add <cartella>` (accetta anche URL o repo GitHub). La cartella contiene `.claude-plugin/marketplace.json`; ogni voce ha `name` e `source`, con percorso relativo alla radice della cartella. Poi `claude plugin install <plugin>@<marketplace> --scope user|project|local`. Fonti: `claude plugin marketplace add --help`, `claude plugin install --help`; https://code.claude.com/docs/en/plugin-marketplaces.md; https://code.claude.com/docs/en/plugins/install.md.
- Solo per una sessione, senza installare: `claude --plugin-dir <cartella-del-plugin>` (accetta anche un `.zip`). Fonti: `claude --help`; https://code.claude.com/docs/en/plugins/create.md.
- Skill: una cartella `<nome>/SKILL.md` in `~/.claude/skills/` (personale) o in `.claude/skills/` (progetto). Una cartella lì con `.claude-plugin/plugin.json` diventa un plugin `<nome>@skills-dir`. Fonti: `claude plugin --help` (voce `init`: «Scaffold a new plugin at ~/.claude/skills/<name>/»); https://code.claude.com/docs/en/skills.
- Aggiornare: `claude plugin update <plugin>@<marketplace>` (serve un riavvio); `claude plugin marketplace update [nome]`. Fonte: `claude plugin update --help`, `claude plugin marketplace --help`.
- Togliere: `claude plugin uninstall <plugin>` (con `--scope`); `claude plugin marketplace remove <nome>`. Per una skill basta togliere la cartella. Fonte: `claude plugin uninstall --help`, `claude plugin marketplace --help`.

**A2. Lancio senza mani: sì.**
- Prompt: `claude -p "<prompt>"` (o `--print`). Cartella di lavoro: quella da cui si lancia il processo; `--add-dir <cartella…>` aggiunge accessi. Fonte: `claude --help`.
- Modello: `--model <alias|nome completo>`. Alias documentati: `default`, `best`, `fable`, `opus`, `sonnet`, `haiku`, `opusplan`. Fonti: `claude --help`; https://code.claude.com/docs/en/model-config.md.
- Permessi: `--permission-mode <modo>`, con scelte `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`, `plan` (`claude --help`). Il modo che chiede conferma per ogni azione («Manual» nella CLI) è `default` nei file di configurazione e negli hook (https://code.claude.com/docs/en/permission-modes.md).
  - Sola lettura: `--permission-mode plan`, oppure, più stretto, `--tools "Read,Grep,Glob"` (`--tools` sostituisce l'elenco; `""` spegne tutti gli strumenti; `claude --help`).
  - Approvare tutto: `--permission-mode bypassPermissions` oppure `--dangerously-skip-permissions` (`claude --help`; la CLI avverte di usarlo solo in sandbox).
  - Regole precise: `--allowedTools "Bash(git diff *),Read"` e `--disallowedTools` (`claude --help`).
- Uscita in formato macchina: `--output-format json` (un oggetto alla fine) o `stream-json` (righe JSON in tempo reale; negli esempi della doc è usato con `--verbose`). Il JSON contiene `session_id`, `usage` e `total_cost_usd` (https://code.claude.com/docs/en/headless.md).
- Ripresa: `claude -p --resume <session-id>`. Le sessioni create con `-p` restano fuori da `claude --continue`; per continuarle con `--continue` serve `claude -p --continue` (https://code.claude.com/docs/en/sessions.md).
- Identificativo della nuova sessione: lo si fissa in partenza con `--session-id <uuid>` (UUID valido; `claude --help`), oppure lo si legge dal campo `session_id` del JSON (https://code.claude.com/docs/en/headless.md, esempio `jq -r '.session_id'`).

**A3. Elenco dei modelli: non trovato come comando.** Nessun sottocomando dell'aiuto li elenca (`claude --help`). Il selettore `/model` li mostra in sessione interattiva (https://code.claude.com/docs/en/model-config.md). Gli ID completi negli esempi della doc sono del tipo `claude-opus-5-5`, `claude-sonnet-5`, `claude-fable-5-1`.

**A4. Trascrizioni e contatori: sì.**
- Forma: `~/.claude/projects/<progetto>/<session-id>.jsonl`. `<progetto>` è il percorso della cartella di lavoro con i caratteri non alfanumerici sostituiti da `-`; per i nomi oltre 200 caratteri il nome viene troncato e seguito da un hash (https://code.claude.com/docs/en/sessions.md). La forma è confermata sui file locali.
- Tipi di record osservati nei file locali (solo nomi): `user`, `assistant`, `system`, `attachment`, `file-history-snapshot`, `ai-title`, `agent-name`, `last-prompt`, `queue-operation`, `pr-link`, `cost-state`, `api-request`, `api-request-blob`, `api-request-shape`.
- Contatori, nel campo `message.usage` dei record `assistant` (solo nomi osservati): `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `cache_creation.ephemeral_5m_input_tokens`, `cache_creation.ephemeral_1h_input_tokens`, `output_tokens_details.thinking_tokens`, `server_tool_use.web_search_requests`, `server_tool_use.web_fetch_requests`.
- Con OpenTelemetry il conteggio è la metrica `claude_code.token.usage` con attributo `type` = `input`, `output`, `cacheRead`, `cacheCreation` (https://code.claude.com/docs/en/monitoring-usage.md).

**A5. Quota esaurita: sì.** Testi dalla pagina errori, sezione «Usage limits» (https://code.claude.com/docs/en/errors.md):
- `You've hit your session limit · resets 3:45pm`
- `You've hit your weekly limit · resets Mon 12:00am`
- `You've hit your Opus limit · resets 3:45pm` e `You've hit your Sonnet limit · resets 3:45pm` (limiti per famiglia di modelli)
- limiti di spesa: `You've hit your monthly spend limit`, `You've hit your individual spend limit`, `You've hit your org's monthly spend limit`, `You've hit your team's shared budget`.

Nello `stream-json` l'evento `api_retry` ha un campo `error` con categorie come `rate_limit` e `billing_error` (https://code.claude.com/docs/en/headless.md). Il messaggio `rate limited until …` in `/usage` indica solo che le quote non si possono rileggere per ora, non che il lavoro è bloccato (https://code.claude.com/docs/en/costs.md).

**A6. Versione e accesso: sì.**
- Versione: `claude --version` → `2.1.319 (Claude Code)`.
- Accesso: `claude auth status`, con `--json` (predefinito) o `--text`; esce con 0 se si è dentro, 1 se no (`claude auth status --help`; https://code.claude.com/docs/en/cli-reference.md). Non l'ho eseguito. La doc non dice se fa chiamate di rete: da verificare che non spenda quota.

**A7. Sotto-agenti: sì.**
- Lo strumento `Agent` lancia un sotto-agente. Le definizioni hanno un campo `model`: `sonnet`, `opus`, `haiku`, `fable`, un ID completo oppure `inherit` (eredita il modello della conversazione; è il default). Fonte: https://code.claude.com/docs/en/sub-agents.md.
- Agenti di sistema: `Explore` usa il modello della conversazione principale (con eccezioni per Fable); `statusline-setup` usa Sonnet; `claude-code-guide` usa Haiku; `claude` segue l'ordine dei modelli. Fonte: stessa pagina.
- Da riga di comando: `--agents '<json>'` definisce agenti solo per la sessione (`claude --help`). `CLAUDE_CODE_SUBAGENT_MODEL` impone un modello a tutti i sotto-agenti (doc sub-agents).

**A8. Skill e istruzioni di progetto: sì.**
- Istruzioni: `./CLAUDE.md` o `./.claude/CLAUDE.md` (progetto); `~/.claude/CLAUDE.md` (utente). `AGENTS.md` viene letto solo se nella cartella di lavoro o sopra non c'è un `CLAUDE.md`, oppure se un `CLAUDE.md` lo importa con `@AGENTS.md` (https://code.claude.com/docs/en/memory.md).
- Skill: `~/.claude/skills/<nome>/SKILL.md`; `.claude/skills/<nome>/SKILL.md`, anche nelle cartelle superiori fino alla radice del repo; `<plugin>/skills/<nome>/SKILL.md` (https://code.claude.com/docs/en/skills.md).

## B. Antigravity (`agy`)

**B1. Plugin e skill da cartella locale: sì per i plugin; skill via cartella.**
- Plugin: `agy plugin install </percorso/del/plugin>` installa da una cartella locale, come da https://antigravity.google/docs/plugins?tab=cli («CLI shell subcommands»). Togliere: `agy plugin uninstall <nome>`; sospendere: `agy plugin disable|enable <nome>` (`agy plugin --help`).
- A mano: la cartella del plugin va in `.agents/plugins/` del progetto o in `~/.gemini/config/plugins/` a livello globale (https://antigravity.google/docs/plugins?tab=cli, «Manual plugin installation»). Il percorso `~/.gemini/config/plugins/<nome>` è confermato da `agy plugin list --json`.
- Aggiornare: **non trovato**. `agy plugin --help` elenca `list`, `import`, `install`, `uninstall`, `enable`, `disable`, `validate`, `link`, `help`: nessun `update`.
- Marketplace in cartella: **non trovato**. La doc dice che il suffisso `@marketplace` accetta solo `antigravity-plugins-official`. `agy plugin link <mp> <target>` «genera un link a un marketplace» (aiuto), ma non l'ho verificato.
- Skill: `<progetto>/.agents/skills/<nome>/SKILL.md` oppure `~/.gemini/config/skills/<nome>/SKILL.md` (https://antigravity.google/docs/skills). Togliere: rimuovere la cartella.
- Nota: un riepilogo di ricerca web (non una fonte ufficiale) indicava `~/.gemini/antigravity-cli/plugins/` come cartella dei plugin. La doc ufficiale e `agy plugin list --json` danno `~/.gemini/config/plugins/`: vale quella.

**B2. Lancio senza mani: sì.**
- Prompt: `agy -p "<prompt>"` (`--print`, `--prompt`). Cartella: quella corrente; `--add-dir <cartella>` per altre. Le conversazioni sono legate alla cartella (https://antigravity.google/docs/cli/conversations; `agy --help`).
- Modello: `--model <nome>` (vedi B3). Impegno di ragionamento: `--effort low|medium|high|xhigh|max`. Agente: `--agent <nome>` (`agy --help`).
- Permessi: `--mode accept-edits|auto|plan` (`agy --help`). Senza `--mode` vale la modalità `default` («request-review»), che si ferma prima di scrivere file. `plan` aggiunge al prompt l'istruzione `/plan` per analizzare e pianificare prima di scrivere codice; la pagina delle modalità non lo descrive come blocco delle scritture (https://antigravity.google/docs/cli/modes).
  - Sola lettura vera: regole `deny` nel blocco `permissions` di `~/.gemini/antigravity-cli/settings.json`, per esempio `write_file(*)` e `command(*)`. Precedenza: Deny, poi Ask, poi Allow (https://antigravity.google/docs/permissions). Non l'ho provato.
  - Approvare tutto: `--dangerously-skip-permissions` (`agy --help`; la doc avverte del rischio).
- Uscita in formato macchina: `--output-format json` (una busta alla fine) o `stream-json` (NDJSON con eventi `init`, `step_update`, `result`). Si aggiungono `--json-schema` per l'output strutturato e `--print-timeout` (0 = fino alla fine del turno) (https://antigravity.google/docs/cli/headless).
- Ripresa: `agy -p --conversation <id>`, con un ID preso da un run precedente, oppure `-c/--continue` per l'ultima della cartella (`agy --help`; https://antigravity.google/docs/cli/headless).
- Identificativo: nella busta JSON è il campo `conversation_id`; nello `stream-json` è in `init.conversation_id` e in `result` (https://antigravity.google/docs/cli/headless). Fissarlo in partenza: **non trovato** (nessun flag).

**B3. Elenco dei modelli: sì.** `agy models` («List available models», `agy --help`; non eseguito). La pagina dei modelli (https://antigravity.google/docs/models) elenca, con i nomi di visualizzazione e il livello indicato nella pagina: Gemini 4 Argon (High); Gemini 3.8 Flash (Medium); Gemini 3.7 Flash (Medium); Gemini 3.6 Flash (Medium); Gemini 3.1 Pro (High); Claude Sonnet 5.5 (Thinking); Claude Opus 5.5 (Thinking); Claude Sonnet 4.6 (Thinking); Claude Opus 4.6 (Thinking); GPT-OSS 120B (Medium). Un modello non riconosciuto dà errore con l'elenco dei disponibili nel campo `error` (https://antigravity.google/docs/cli/headless).

**B4. Trascrizioni e contatori: sì.**
- Conversazioni: `~/.gemini/antigravity-cli/conversations/<id>.db`, file SQLite (osservati sui file locali). Accanto, la cartella `~/.gemini/antigravity-cli/brain/<id>/` (osservata).
- Tabelle del database (solo nomi): `steps` (campi `idx`, `step_type`, `status`, `metadata`, `error_details`, `permissions`, `task_details`, `render_info`, `step_payload`, `step_format`), `trajectory_meta` (`trajectory_id`, `cascade_id`, `trajectory_type`, `source`), `gen_metadata`, `trajectory_metadata_blob`, `executor_metadata`, `battle_mode_infos`, `parent_references`. La doc non le descrive.
- Contatori: nell'uscita headless, l'oggetto `usage` con `input_tokens`, `output_tokens`, `thinking_tokens`, `cache_read_tokens`, `total_tokens`; in `stream-json` lo stesso `usage` compare in ogni `step_update` (https://antigravity.google/docs/cli/headless). Nel database non ho trovato questi contatori per nome: sono probabilmente dentro campi BLOB, da verificare.

**B5. Quota esaurita: non trovato.** La doc non riporta il testo dell'errore di quota (controllate le pagine headless, troubleshooting, credits e usage). Quote: `/usage` (alias `/quota`, in sessione interattiva) mostra le quote per gruppo di modelli, con limite settimanale e limite di cinque ore (https://antigravity.google/docs/cli/commands/usage). Crediti: l'impostazione «Use AI Credits» permette di usare i crediti quando le quote del piano sono esaurite (https://antigravity.google/docs/cli/credits). In headless un esito diverso da `SUCCESS` ha `status` `ERROR`, `CANCELED`, `INTERRUPTED`, `INVALID` o `WAITING`, con il motivo nel campo `error` (https://antigravity.google/docs/cli/headless).

**B6. Versione e accesso.**
- Versione: `agy --version` → `1.5.3` (verificato).
- Accesso senza quota: **non trovato**. L'aiuto non ha un sottocomando di stato (`agy --help`). La doc dice che il run headless usa le credenziali in cache e che, senza accesso, termina con un errore «authentication required» (https://antigravity.google/docs/cli/headless). Un test del genere lancia un run, quindi non è un controllo senza quota.

**B7. Sotto-agenti: sì, con livelli di modello.**
- Lo strumento `invoke_subagent` lancia un sotto-agente di tipo `research` (ricerca nel codice e nei file) o `self` (copia dell'agente chiamante) (https://antigravity.google/docs/subagents).
- Agenti propri: nel frontmatter `subagent: true`, `model: inherit | flash | pro` (livelli, non nomi di modelli), `tools`, `mcpServers` (stessa pagina).
- Modelli concreti per livello: **non trovato**.

**B8. Skill e istruzioni di progetto: sì.**
- Istruzioni: `AGENTS.md` e `GEMINI.md` nella cartella di lavoro e in ciascuna cartella superiore fino alla radice del repo; `~/.gemini/AGENTS.md` e `~/.gemini/GEMINI.md` per tutto l'utente. Ad ogni livello si legge anche la cartella `.agents/`, con le regole `rules/*.md` (https://antigravity.google/docs/customization-discovery). Le sottocartelle sotto la cartella di lavoro non vengono cercate: un `AGENTS.md` lì vale solo se la sessione parte da quella cartella (stessa pagina).

- Skill: `<progetto>/.agents/skills/<nome>/SKILL.md`, `~/.gemini/config/skills/<nome>/SKILL.md`; la CLI legge anche `~/.gemini/antigravity-cli/skills/` e `~/.gemini/skills/` (https://antigravity.google/docs/skills; https://antigravity.google/docs/customization-discovery).

## C. Pi (`pi`, non installato)

**C1. Plugin e skill da cartella locale: sì.**
- Pacchetto da cartella: `pi install ./<cartella>`. Ci sono anche `npm:<pacchetto>@<versione>` e `git:<repo>@<ref>`. Il percorso locale si carica senza copiare: un aggiornamento è una modifica dei file della cartella (per esempio un `git pull` dentro). Le installazioni personali vanno in `~/.pi/agent/settings.json`; con `-l` vanno in `.pi/settings.json` del progetto, e solo dopo la fiducia nel progetto (`packages.md`, `cli.md`; pacchetto 1.5.0).
- Togliere: `pi remove <sorgente>` (alias `pi uninstall`). Aggiornare: `pi update <sorgente>`, oppure `pi update --extensions` per tutti (`cli.md`, sezione «Update Pi or packages»).
- Forma del pacchetto: cartella o pacchetto npm con `package.json` che contiene la chiave `pi` (`extensions`, `skills`) o cartelle convenzionali (`packages.md`). Esempio locale da leggere: `~/.claude/plugins/cache/claude-plugins-official/superpowers/7.0.0/package.json`, con la parola chiave `pi-package`.
- Skill senza pacchetto: `<agent-dir>/skills/` (con `<agent-dir>` = `~/.pi/agent`), `.pi/skills/` (progetto), `~/.agents/skills/` e `.agents/skills/` (risalendo fino alla radice del repo). `--skill <percorso>` le carica per un solo lancio (`skills.md`, `configuration.md`).
- Marketplace: **non trovato** (Pi usa npm, git o percorsi locali).

**C2. Lancio senza mani: sì.**
- Prompt: `pi -p "<prompt>"` (`--print`): scrive il testo finale su stdout ed esce. `pi --mode json "<prompt>"` scrive JSONL su stdout ed esce (`cli.md`).
- Cartella: quella corrente; i percorsi relativi partono da lì (`cli.md`).
- Modello: `--model provider/id[:thinking]`, `--provider <nome>`, `--thinking off|minimal|low|medium|high|xhigh|max` (`cli.md`).
- Permessi: Pi non chiede conferma per ogni chiamata a uno strumento (`security.md`). Sola lettura: `--tools read,grep,find,ls`; `-nt`/`--no-tools` spegne tutti gli strumenti. Strumenti di base: `read`, `bash`, `edit`, `write` (`cli.md`). Approvare tutto è il comportamento predefinito. `-a`/`--approve` si fida dei file di progetto, `-na`/`--no-approve` li ignora (`cli.md`).
- Uscita in formato macchina: `--mode json` (`json.md`).
- Ripresa: `-c`/`--continue` (ultima sessione della cartella), `-r`/`--resume` (selettore), `--session <percorso|id>`, `--fork <percorso|id>`. `--session-id <id>` apre la sessione con quell'ID o la crea (lettere, numeri, `.`, `_`, `-`; `cli.md`).
- Identificativo della sessione appena fatta: la prima riga di `--mode json` è un record `{"type":"session", …, "id": …}` (`json.md`). In modalità RPC si usa il comando `get_state` (`json.md`).

**C3. Elenco dei modelli: sì.** `pi --list-models [ricerca]` elenca i modelli e termina (`cli.md`). Il catalogo è su https://pi.dev/models (`models.md`). L'ultimo elenco scaricato viene salvato e usato anche offline e con `pi -p` (`providers.md`).

**C4. Trascrizioni e contatori: sì.**
- Forma: `~/.pi/agent/sessions/--<percorso-cartella>--/<timestamp>_<session-id>.jsonl`. Nel percorso si toglie il separatore iniziale e `/`, `\` e `:` diventano `-`. La cartella si cambia con `PI_CODING_AGENT_SESSION_DIR` o `--session-dir` (`session-format.md`, `environment-variables.md`).
- Contatori, nel campo `usage` dei messaggi `assistant`: `input`, `output`, `cacheRead`, `cacheWrite`, `cacheWrite1h` (facoltativo), `totalTokens`, e `cost` con `input`, `output`, `cacheRead`, `cacheWrite`, `total` (`message-types.md`).
- Esistono anche record `usage` separati, con un campo `kind` (per esempio `cache_warm`) (`session-format.md`).

**C5. Quota esaurita: non trovato.** La doc non riporta testi di quota (cercato in `usage.md`, `providers.md`, `models.md`, `security.md`, `json.md`, `message-types.md`). Gli errori del provider finiscono in `errorMessage`, in un messaggio con `stopReason: "error"` (`message-types.md`). I tentativi automatici sono eventi `auto_retry_start` con `errorMessage` (esempio: `529 overloaded`, `json.md`).

**C6. Versione e accesso.**
- Versione: `pi --version` (`cli.md`). Non eseguito: `pi` non è installato. Registro npm: 1.5.0.
- Accesso: **non trovato** un comando non interattivo di verifica. `/login [provider]` in sessione interattiva salva la credenziale in `<agent-dir>/auth.json` (`providers.md`).

**C7. Sotto-agenti: no nel core.** Il README dice che Pi non include sotto-agenti né modo piano («skips features like sub-agents and plan mode»). Il riferimento `pi-tools.md` della cache di superpowers cita un pacchetto esterno, `pi-subagents`, come strumento opzionale; i suoi modelli non li ho verificati.

**C8. Skill e istruzioni di progetto: sì.**
- Istruzioni: `AGENTS.md`, `AGENTS.override.md` o `CLAUDE.md` nella cartella `<agent-dir>`, nella cartella di lavoro e nelle superiori. `-nc`/`--no-context-files` le disattiva (`configuration.md`, `cli.md`). `GEMINI.md` non è citato: no.
- Skill: vedi C1.

## D. GitHub Copilot CLI (`copilot`)

**D1. Plugin e skill da cartella locale: sì, con una riserva.**
- Marketplace in cartella: `copilot plugin marketplace add <cartella>` (l'aiuto del 1.0.32 dice «owner/repo for GitHub, URL, or local path»), poi `copilot plugin install <plugin>@<marketplace>`.
- Installazione diretta da percorso: la documentazione la prevede, «Local path: ./my-plugin or /abs/path» (https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference). Il 1.0.32 però avvisa nel suo codice: «Direct plugin installs (repos, URLs, local paths) are deprecated. Only plugin@marketplace installs will be supported in a future release.» (`app.js`). Il marketplace in cartella è la via da preferire.
- Aggiornare: `copilot plugin update <nome>` (la doc aggiunge `--all`). Un plugin di un marketplace locale si carica dal suo percorso reale: le modifiche valgono dopo `/restart` o in una sessione nuova (cli-plugin-reference).
- Togliere: `copilot plugin uninstall <nome>`; `copilot plugin marketplace remove <nome>` (rifiutato se ci sono plugin installati, salvo `--force`) (`copilot plugin --help` e cli-plugin-reference).
- Solo per una sessione: `copilot --plugin-dir <cartella>` (`copilot --help`).
- Skill: personali in `~/.copilot/skills/`, `~/.agents/skills/`, `~/.claude/skills/`; di progetto in `.github/skills/`, `.agents/skills/`, `.claude/skills/`. Dentro una sessione: `/skills add <cartella>`. Da riga di comando: `copilot skill` con add, remove, list, enable, disable (add-skills della doc). Questo sottocomando non compare nell'aiuto del 1.0.32: da verificare.

**D2. Lancio senza mani: sì.**
- Prompt: `copilot -p "<prompt>"`. `-s`/`--silent` stampa solo la risposta (`copilot --help`).
- Cartella: `-C <cartella>` (cli-command-reference); nell'aiuto del 1.0.32 non c'è: da verificare. `--add-dir <cartella>` dà accesso e carica skill e agenti di `.github/`, `.agents/`, `.claude/` (`copilot --help`; cli-command-reference).
- Modello: `--model <id>` (`copilot --help`; esempio in choose-a-model: `copilot --model MODEL-NAME -p "…"`).
- Permessi: `--allow-all-tools` è obbligatorio in modo non interattivo (`copilot --help`). Si possono usare `--allow-tool` e `--deny-tool` (esempi: `--deny-tool=write`, `--allow-tool='shell(git:*)'`), `--available-tools=<elenco>` (solo quegli strumenti; esempio nella doc: `bash,edit,view,grep,glob`), `--excluded-tools`, `--allow-all-paths`, `--allow-url`, `--no-ask-user`. `--yolo` o `--allow-all` attivano tutto (`copilot --help`; allowing-tools). Sola lettura: `--available-tools='view,grep,glob'` (nomi dalla doc). Modo: `--mode interactive|plan|autopilot`, oppure `--plan` (`copilot --help`).
- Uscita in formato macchina: `--output-format json`, JSONL con un oggetto per riga (`copilot --help`).
- Ripresa: `--continue` (ultima sessione; nella doc, prima quella della cartella e poi la più recente in assoluto), `--resume[=ID]` (`copilot --help`), `--session-id <ID>` (crea o riprende con quell'ID; nella doc di cli-command-reference, non nell'aiuto 1.0.32: da verificare).
- Identificativo della sessione appena creata: l'evento `session.start` ha `data.sessionId` (verificato nel `events.jsonl` locale e nello schema `session-events.schema.json`). Il riepilogo di uscita di `-p` riporta un suggerimento `copilot --resume=<SESSION-ID>` (cli-command-reference). `--share[=percorso]` scrive un Markdown con predefinito `./copilot-session-<ID>.md` (`copilot --help`).

**D3. Elenco dei modelli: sì.** `--model` e `/model` in sessione interattiva (`copilot --help`, `copilot help commands`).
- Esempi di ID nell'aiuto del 1.0.32 (`copilot help config`, campo `model`): `claude-sonnet-4.6`, `claude-sonnet-4.5`, `claude-haiku-4.5`, `claude-opus-4.7`, `claude-opus-4.6`, `claude-opus-4.6-fast`, `claude-opus-4.5`, `claude-sonnet-4`, `gpt-5.4`, `gpt-5.3-codex`, `gpt-5.2-codex`, `gpt-5.2`, `gpt-5.1`, `gpt-5.4-mini`, `gpt-5-mini`, `gpt-4.1`.
- L'elenco dei docs correnti (https://docs.github.com/en/copilot/reference/ai-models/supported-models) è più recente e usa altri nomi, per esempio «Claude Sonnet 5.5», «Claude Haiku 5.5», «GPT-6 Sol», «Gemini 3.8 Flash». Non ho verificato che la 1.0.32 li accetti.

**D4. Trascrizioni e contatori: sì.**
- Forma: `~/.copilot/session-state/<uuid>/events.jsonl`, con `workspace.yaml` (campi: `id`, `cwd`, `summary_count`, `created_at`, `updated_at`, `summary`) e le cartelle `files/`, `checkpoints/`, `research/`. I log stanno in `~/.copilot/logs/`. La cartella si cambia con `COPILOT_HOME` o `--config-dir` (`copilot help environment`; https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference).
- Tipi di evento osservati (solo nomi): `session.start`, `session.model_change`, `session.context_changed`, `session.shutdown`, `user.message`, `system.message`, `assistant.turn_start`, `assistant.message`, `assistant.turn_end`, `tool.execution_start`, `tool.execution_complete`.
- Contatori, nell'evento `session.shutdown`: `data.totalPremiumRequests`, `data.conversationTokens`, `data.currentTokens`, `data.systemTokens`, `data.toolDefinitionsTokens`, `data.totalApiDurationMs`. Per ogni modello, in `data.modelMetrics.<modello>`: `usage` con `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens`, e `requests` con `count` e `cost` (schema e file locali).
- Facoltativo, OpenTelemetry: `COPILOT_OTEL_FILE_EXPORTER_PATH` scrive JSON-lines, con la metrica `gen_ai.client.token.usage` (`copilot help monitoring`).

**D5. Quota esaurita: sì (dal sorgente 1.0.32).** Stringhe fisse nel file `app.js` del pacchetto `@github/copilot@1.0.32`:
- `Quota exceeded. Upgrade to increase your limit: https://github.com/settings/copilot/features`
- HTTP 402 in un job: `No remaining quota for premium requests`
- limite di frequenza: `You've hit your global rate limit.`, seguito da «Please wait for your limit to reset»
- avvisi quando la quota scende al 10% o meno, per la quota settimanale e per quella di sessione (`weekly usage limit`, `session usage limit`).
Il testo non è verificato in una sessione reale.

Le pagine dei docs indicano `gh auth status` per il login GitHub, e le variabili `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN` (https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/troubleshoot-copilot-cli-auth; `copilot help environment`). `copilot login` autentica, ma non è stato eseguito.

**D7. Sotto-agenti: sì.**
- Agenti integrati, dai file `definitions/*.agent.yaml` del pacchetto 1.0.32: `task` (`claude-haiku-4.5`), `explore` (`claude-haiku-4.5`), `research` (`claude-sonnet-4.6`), `code-review` (`claude-sonnet-4.5`), `configure-copilot` (`claude-haiku-4.5`), `rubber-duck` (nessun campo `model`).
- Agenti propri: file `.agent.md` con i campi `model`, `model-policy` e `tools` (https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli).

**D8. Skill e istruzioni di progetto: sì.**
- Istruzioni (dal codice di `app.js` e dalla doc https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions): `.github/copilot-instructions.md`; `AGENTS.md` nella radice; `CLAUDE.md` nella radice o in `.claude/CLAUDE.md`; `GEMINI.md` nella radice; `~/.copilot/copilot-instructions.md` per tutto l'utente; le cartelle di `COPILOT_CUSTOM_INSTRUCTIONS_DIRS`. `--no-custom-instructions` le disattiva (`copilot --help`).
- Skill: vedi D1.
