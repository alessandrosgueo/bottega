# B0 L'officina: piano dettagliato

> **Per chi esegue:** metodo scelto al passaggio di consegne; i passi usano le caselle (`- [ ]`). Vale tutto il piano
> delle tappe (`docs/plans/2026-11-08-tappe.md`): Ruling, Global Constraints, Review Focus.

**Obiettivo:** lo scheletro del repo `bottega`, il comando `bottega` con la versione e il controllo pubblico, la CI sui
runner di GitHub e il repo privato su GitHub.

**Architettura:** pacchetto Python di sola libreria standard in `attrezzi/bottega/`, lanciato come
`python3 -m bottega`; prove in `attrezzi/tests/` con `pytest` (solo sviluppo); una CI che fa prove, controllo dei dati
personali e scansione dei segreti.

**Tecnologie:** Python 3.11+ (sviluppo su 3.12), `uv`, `pytest`, GitHub Actions su `ubuntu-24.04`, gitleaks 8.30.1.

**Design:** `docs/specs/2026-11-08-metodo-design.md`.

## Global Constraints

Quelle del piano delle tappe, più: il controllo pubblico non scrive mai nei log la parola vietata che ha trovato (i log
di un repo pubblico sono pubblici), solo il suo numero nell'elenco.

## Review Focus

1. **Una parola vietata scritta con altre maiuscole** («MarioRossi» per «mariorossi») va trovata: test in Task 2.
2. **Il log del controllo** non deve contenere la parola trovata: test in Task 2.
3. **Segnaposto legittimi** (`/home/<utente>/`, `02:00:00:00:00:01`, `192.0.2.1`, `noreply@…`) non sono dati
   personali: test in Task 2.
4. **`PAROLE_VIETATE` vuota o assente** (per esempio su una PR da un fork): il controllo gira lo stesso sulle altre
   regole e lo dice in una riga: test in Task 2.
5. **Un file binario** nel repo non fa cadere il controllo: test in Task 2.

### Task 2: Il controllo pubblico

**Files:**
- Create: `attrezzi/bottega/pubblico.py`
- Modify: `attrezzi/bottega/__main__.py` (sottocomando `controlla-pubblico`)
- Test: `attrezzi/tests/test_pubblico.py`

**Interfaces:**
- Consumes: `COMANDI` del Task 1, che tiene solo nome e funzione. Per gli argomenti il Task 2 aggiunge accanto
  `ARGOMENTI: dict[str, Callable[[argparse.ArgumentParser], None]]` (facoltativo per comando), che
  `costruisci_parser` chiama sul sottoparser; ogni sottocomando ha `help=` dalla prima riga della docstring della sua
  funzione. La registrazione sta in `__main__.py`, mai nel modulo del comando: con `python -m bottega` il modulo che
  gira è `__main__`, non `bottega.__main__`, e una registrazione fatta da fuori finirebbe in un'altra copia.
- Produces:
  - `@dataclass(frozen=True) class Trovata: percorso: str; riga: int; motivo: str`
  - `cerca(testo: str, percorso: str, vietate: Sequence[str]) -> list[Trovata]`
  - `controlla(radice: Path, vietate: Sequence[str]) -> list[Trovata]`: solo i file che `git ls-files` elenca; un file
    che non si decodifica in UTF-8 si salta.
  - `vietate_da_ambiente(valore: str | None) -> list[str]`: separa `PAROLE_VIETATE` su virgole e a capo, toglie
    spazi e vuoti.
  - CLI: `python3 -m bottega controlla-pubblico [--radice PERCORSO]`; stampa `percorso:riga: motivo`, esce 1 se trova,
    0 se no; con l'elenco vuoto stampa una riga «nessuna parola vietata: controllo solo delle regole fisse».

I motivi, testo esatto: `parola vietata n.<i>` (indice da 1 nell'elenco), `percorso di casa`, `indirizzo email`,
`indirizzo IP privato`, `indirizzo MAC`. Le regole fisse: percorsi `/home/<nome>/` e `C:\Users\<nome>\` con un nome
che non sia `<utente>`, `utente` o `nome`; email tranne i domini `example.com`, `example.org` e gli indirizzi che
cominciano con `noreply`; IPv4 in `10/8`, `172.16/12`, `192.168/16` (i documenti usano `192.0.2.0/24`);
MAC tranne quelli che cominciano con `02:00:00:00:00:`.

- [ ] **Step 1: Scrivi le prove che falliscono**

```python
def test_parola_vietata_senza_badare_alle_maiuscole():
    t = cerca("ciao MarioRossi", "a.md", ["mariorossi"])
    assert t == [Trovata("a.md", 1, "parola vietata n.1")]

def test_il_motivo_non_ripete_la_parola():
    assert all("mario" not in x.motivo.lower() for x in cerca("mariorossi", "a.md", ["mariorossi"]))

# gli esempi si compongono mentre la prova gira: nel repo non compaiono mai per intero,
# così il controllo pubblico non trova se stesso
@pytest.mark.parametrize("testo,motivo", [
    ("/ho" + "me/pippo/x", "percorso di casa"), ("scrivi a a" + "@b.it", "indirizzo email"),
    ("192." + "168.1.42", "indirizzo IP privato"), (":".join(["aa", "bb", "cc", "dd", "ee", "ff"]), "indirizzo MAC"),
])
def test_regole_fisse(testo, motivo):
    assert [x.motivo for x in cerca(testo, "a.md", [])] == [motivo]

@pytest.mark.parametrize("testo", ["/home/<utente>/x", "02:00:00:00:00:01", "192.0.2.1",
                                   "noreply@example.com", "x@example.org"])
def test_segnaposto_ammessi(testo):
    assert cerca(testo, "a.md", []) == []

def test_vietate_da_ambiente():
    assert vietate_da_ambiente(" a, b\nc ,,") == ["a", "b", "c"]
    assert vietate_da_ambiente(None) == []

def test_cli_trova_ed_esce_1(tmp_path, monkeypatch, capsys):
    # repo git di prova con un file di testo che contiene la parola e un file binario
    ...
    monkeypatch.setenv("PAROLE_VIETATE", "parolafinta")
    assert main(["controlla-pubblico", "--radice", str(tmp_path)]) == 1
    out = capsys.readouterr().out
    assert "parola vietata n.1" in out and "parolafinta" not in out

def test_cli_senza_elenco(tmp_path, monkeypatch, capsys):
    # repo git di prova pulito
    ...
    monkeypatch.delenv("PAROLE_VIETATE", raising=False)
    assert main(["controlla-pubblico", "--radice", str(tmp_path)]) == 0
    assert "nessuna parola vietata" in capsys.readouterr().out
```

`tmp_path`; il binario è un file con `b"\xff\xfe\x00"`.

Ruling del garzone accettati in B0.1: `uso:` con un formattatore proprio; `[build-system]` setuptools (senza, uv tratta
il progetto come virtuale e `uv run python -m bottega` non trova il pacchetto); versione in un solo posto
(`attr = "bottega.VERSIONE"`); niente `.python-version` (un amico con un altro Python ≥ 3.11 non deve scaricarne uno; la
CI prova 3.12). Il maestro anticipa il passo 1 del Task 4 (identità `noreply`) a prima del commit di B0.1.

Per le tappe dopo: `python3 -m bottega` funziona da `uv run` o con `PYTHONPATH=attrezzi`, non da solo nella radice;
l'installazione (B6) e i workflow (B3) devono dirlo o usare `uv run`.
