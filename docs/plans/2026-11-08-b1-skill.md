# B1 La skill e le porte: piano dettagliato

> **Per chi esegue:** metodo Bottega; i passi usano le caselle (`- [ ]`). Vale tutto il piano delle tappe
> (`docs/plans/2026-11-08-tappe.md`): Ruling, Global Constraints, Review Focus. Vale la costituzione del repo
> (`docs/costituzione.md`, scritta nel Task 2).

**Obiettivo:** la skill generica `bottega` con una pagina per porta, i modelli (brief, costituzione, `AGENTS.md`), il
formato di quaderni e casistica, le cartelle plugin delle quattro porte; la skill si installa in Claude Code e in
Antigravity dal clone e regge un banco di prova su 10 casi.

**Architettura:** il plugin in `plugin/` (`plugin/skills/bottega/` con la skill, `porte/`, `modelli/`, e i manifesti
delle porte); il marketplace di Claude Code alla radice; `quaderni/` e `casistica/` alla radice; un modulo `bottega.casi` che legge la
casistica, con le prove.

**Design:** `docs/specs/2026-11-08-metodo-design.md`, sezioni «I concetti», «La vita di un lavoro», «Come impara»,
«Il repo, il plugin e l'installazione».

## Ruling

- **B1-R1. Si installa sempre dal clone locale**, in ogni porta, anche in Claude Code (un marketplace può essere una
  cartella): nessun documento scrive il proprietario del repo, che resta fra le parole vietate; `git pull` resta
  l'unico mezzo di aggiornamento. Corregge il design, che per Claude Code diceva «dal repo GitHub».
- **B1-R2. Nomi:** plugin `bottega`, skill `bottega`, versione dei manifesti = `bottega.VERSIONE`; autore «gli autori
  della bottega», nessuna email.
- **B1-R3. La skill non nomina modelli, fornitori o assetti** (anti-obiettivo del design). Le pagine per porta nominano
  la loro CLI e basta; i quaderni nominano il loro modello (sono dati, non regole).
- **B1-R4. Casistica:** un file per area, `casistica/<area>.md`; ogni caso è una sezione `### <AREA>-<n>. <titolo>` con
  i campi in quest'ordine, uno per riga che comincia col nome in grassetto: `**Scenario:**`, `**Domanda:**`,
  `**Opzioni:**` (righe `- A) …`, `- B) …`), `**Scelta:** <lettera>`, `**Perché:**`, `**Esito:**`, `**Fonte:**`
  (`deciso dall'utente`, `dal vivo AAAA-MM-GG` o `di chi decide`).
- **B1-R6. Il plugin sta in `plugin/`**, separato dai file di sviluppo del repo: Antigravity carica come regola
  l'`AGENTS.md` alla radice di un plugin, e quello della radice del repo parla a chi sviluppa la bottega, non ai
  progetti di chi la installa. Alla radice restano i marketplace (`.claude-plugin/marketplace.json` con
  `source: "./plugin"`, e quello di Copilot CLI se la sua forma lo chiede). Precisa R3 del piano delle tappe.
- **B1-R5. Quaderni:** `quaderni/<modello>.md`, un file per modello (nome del modello in minuscolo, trattini); ogni
  lezione è una riga `- <regola breve> (<riferimento a una PR o a una tappa>)`.

## Interfaces prodotte per le tappe dopo

La skill del Task 2 le promette all'utente; le tappe dopo le costruiscono con questi nomi:
- etichette-comando `bottega: fuori` e `esegue: <nome>`; comandi nei commenti `/bottega riprova`,
  `/bottega consulta <domanda>`, `/bottega sospendi` (B3);
- il campo «Esito» del Project coi valori `pronta per l'unione`, `correzioni`, `rifiutata` (B3);
- una tappa è un'issue madre coi compiti come sotto-issue, in ordine; il «Fatto quando» è un blocco di codice nella
  sezione `## Fatto quando` del corpo dell'issue (B3);
- `DOMANDA PER CHI DECIDE:` chiude il turno di un esecutore che chiede un consulto (B3);
- `bottega ferma|riparti` (B3), `bottega segno inizio <numero dell'issue>|fine` e `bottega conti` (B5), `bottega
  casi [--domande]` (Task 4 qui); il comando `bottega` sul PATH lo mette l'installazione (B6);
- quaderni e casistica di chi usa la bottega in `.github/bottega/quaderni/` e `.github/bottega/casistica/` del suo
  progetto, letti dal fascicolo insieme ai comuni (B3);
- i minori della revisione finale diventano issue del progetto; le PR segnate dal workflow (prove già esistenti
  cambiate, controllo dei segreti) prendono un'etichetta d'allarme (B3).

## Global Constraints

Quelle del piano delle tappe. In più: il banco di prova di questa tappa lo fa un consigliere con la sua porta senza
mani, dalla macchina di chi decide.

## Review Focus

1. **Un lettore che non conosce il progetto** deve poter seguire la skill: niente gergo di un progetto, niente nomi di
   persone o di modelli (prova: il banco del Task 5 e la lettura del consigliere).
2. **Un manifesto con una versione diversa da `VERSIONE`** o un percorso di skill che non esiste: prova in Task 3.
3. **Un caso della casistica senza un campo, con una scelta che non è fra le opzioni o con un'area sbagliata:**
   `bottega.casi` lo segnala con file e riga (prova in Task 4).
4. **Le porte che non hanno un'installazione da cartella:** la pagina della porta dice cosa si fa invece (Task 3).
5. **Il controllo pubblico sui file nuovi:** verde con le parole vietate vere (Task 5).

### Task 1: La ricognizione delle porte (garzone)

**Files:** Create `docs/ricognizioni/2026-11-08-porte.md`.

Per Claude Code, Antigravity, Pi e GitHub Copilot CLI, con la fonte di ogni fatto (`--help` di una CLI installata o
URL della documentazione): installare un plugin o una skill da una cartella locale e toglierlo; lanciare senza mani
(prompt, cartella, modello, sola lettura o permessi, ripresa di una conversazione col suo identificativo); elencare i
modelli; dove stanno le trascrizioni e quali contatori di token hanno; il testo di «quota esaurita»; come si legge la
versione e se l'accesso è valido; se ha sotto-agenti. Nessuna prova che spenda quota (solo `--help`, `--version`,
file di configurazione e documentazione); nessun percorso personale (si scrive `~`).

- [ ] Ricognizione scritta, un capitolo per porta, una tabella finale porta × domanda con «sì/no/non trovato».

### Task 2: La skill, i modelli, i formati (maestro)

**Files:** Create `plugin/skills/bottega/SKILL.md`, `plugin/skills/bottega/modelli/{brief,costituzione,agents}.md`,
`quaderni/LEGGIMI.md`, `casistica/LEGGIMI.md`, `casistica/ciclo.md` (10 casi), `docs/costituzione.md` e `AGENTS.md`
del repo stesso. Modify: il design (tabella spezzata, B1-R1), R9 del piano delle tappe (grammatica).

- [ ] Scritti dal maestro: la skill è la decisione del metodo, non si delega.

### Task 3: Le pagine per porta e le cartelle plugin (garzone)

**Files:** Create `plugin/skills/bottega/porte/{claude-code,antigravity,pi,copilot-cli}.md`,
`plugin/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` alla radice (`source: "./plugin"`),
`plugin/.antigravity-plugin/plugin.json`, `plugin/package.json` per Pi, i file per Copilot CLI che la ricognizione
indica; Test `attrezzi/tests/test_plugin.py`.

**Interfaces:** Consumes la ricognizione del Task 1 e la skill del Task 2 (che rimanda a `porte/<porta>.md`).

- [ ] Prove: `test_manifesti_validi` (JSON valido, nome `bottega`, versione = `VERSIONE`, nessuna email),
  `test_skill_ha_frontmatter` (`name: bottega`, `description` non vuota), `test_percorsi_dei_manifesti_esistono`,
  `test_ogni_porta_ha_la_sua_pagina` (le quattro pagine esistono e la skill le nomina).
- [ ] Le pagine seguono un solo schema: installare dal clone e aggiornare, lavorare senza mani, modelli, trascrizioni
  e contatori, quota esaurita, sotto-agenti, limiti noti. Solo fatti della ricognizione; ciò che manca si scrive «da
  verificare in B3».

### Task 4: La lettura della casistica (garzone)

**Files:** Create `attrezzi/bottega/casi.py`, `attrezzi/tests/test_casi.py`; Modify `__main__.py` (sottocomando
`casi`).

**Interfaces:** Produces `@dataclass(frozen=True) class Caso: id: str; titolo: str; scenario: str; domanda: str;
opzioni: dict[str, str]; scelta: str; perche: str; esito: str; fonte: str; percorso: str; riga: int`,
`leggi(percorso: Path) -> list[Caso]`, `controlla_casistica(cartella: Path) -> list[str]` (errori `file:riga: motivo`),
CLI `python3 -m bottega casi [--cartella casistica] [--domande]`: senza opzioni controlla ed esce 1 se ci sono errori;
con `--domande` stampa i casi senza scelta, perché ed esito (è il foglio del banco di prova). Il banco vero è B5.

- [ ] Prove: un caso valido letto per intero; ogni campo mancante segnalato con la riga; scelta fuori dalle opzioni;
  id che non comincia con l'area del file; due casi con lo stesso id; `--domande` non contiene mai `Scelta`.

### Task 5: Il cancello (maestro)

- [ ] `python3 -m bottega casi` verde sulla casistica vera; controllo pubblico verde con le parole vietate.
- [ ] Claude Code: marketplace dalla cartella del clone, plugin installato con ambito di progetto in una cartella di
  prova; una sessione senza mani lì vede la skill `bottega`. Poi tolto.
- [ ] Antigravity: plugin installato dalla cartella del clone, la skill si vede; poi tolto.
- [ ] Banco a mano: un consigliere senza mani, con la skill e il foglio di `casi --domande`, risponde ai 10 casi; le
  scelte si confrontano con la casistica; ogni divergenza: si corregge la skill o il caso.
- [ ] Revisione finale: la skill la rilegge un consigliere senza mani (critica, non riscrittura); il codice il
  capobottega. Unione, misure, piano di B2.
